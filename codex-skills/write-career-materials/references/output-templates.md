# 输出骨架

## 职称评定项目骨架

```md
### [项目名称]

项目一句话定位：
[它解决什么关键问题，为什么重要]

背景与核心矛盾：
[业务背景]
[系统/组织/工程难点]

关键判断：
[为什么选当前路线，不选其他路线]

方案设计：
[分层/机制/协议/治理/闭环/迁移/观测]

个人职责：
[主导/负责/推动/统筹/打通/建设/沉淀]

项目业绩：
- 规模：[用户数/调用量/端数/覆盖团队]
- 质量：[成功率/稳定性/采纳率/问题闭环率]
- 效率：[耗时下降/研发提效/维护成本下降]
- 杠杆：[复用场景/后续接入/长期资产]

长期沉淀：
[平台/规范/模板/FAQ/监控/评测/方法论]
```

## 简历项目介绍骨架

### 一段版

```md
[项目名称]：面向[用户/场景]建设[能力/平台]，围绕[核心矛盾]做出[关键判断/关键机制]，我主导/负责[职责]，最终实现[最强结果]，并沉淀[长期资产或复用价值]。
```

### Bullet 版

```md
- 面向[场景]，将[原本分散/脆弱/高成本的问题]抽象为[能力/机制/平台]。
- 主导[关键判断/关键架构/关键链路]，解决[最难的边界条件]。
- 将[指标A]提升到[结果]，并支撑[业务范围/用户规模/后续复用]。
```

## 述职/项目介绍骨架

```md
1. 为什么做：当时面临的业务窗口、用户问题或组织挑战。
2. 难点在哪：真正卡住推进的核心矛盾。
3. 我怎么判断：为什么选这条路线。
4. 我做了什么：关键方案和个人职责。
5. 结果如何：数字、案例、范围、反馈。
6. 留下什么：长期资产和后续杠杆。
```

## 高价值句式

- 我负责的不是[表层动作]，而是[更高一层的能力/底座/治理体系]。
- 关键问题不在于[表象]，而在于[真正的边界或矛盾]。
- 为避免[旧方案代价]，我选择将[能力]抽象为[机制/平台/协议]。
- 这项结果不只是[数字变化]，更说明[用户行为改变/系统进入可规模使用态/维护成本被系统性打下]。
- 项目最终沉淀的不只是功能，还包括[规范/工具/监控/评测/方法论]。

## 降级策略

当事实不够强时，不要硬写“大而全”，改用更保守的句式：

- 负责关键模块建设，支撑了[某结果]。
- 主导其中的[某链路/某机制]，解决了[某矛盾]。
- 在[某范围]内验证了方案可行性，并为后续推广打下基础。
